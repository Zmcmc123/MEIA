# MEIA 大体系交互优化设计

> 日期：2026-08-25
>
> 目标分支：`codex/large-system-optimization`
>
> 基线：MEIA `0.11.0`、schema v7、提交 `91837b2`
>
> 状态：待项目所有者审阅；不合并 `main`

## 1. 目标与成功标准

本分支优化大 slab、大量水分子及周期副本场景下的交互体验，同时保持成键、
氢键、周期整理、原子身份和最终导出结果的完整语义。

成功标准：

1. 3D 旋转、缩放和临时原子选择不因 2D 绘制触发 Python 整页阻塞。
2. 大体系确认选择、调整主体/背景强度后，页面立即返回可交互的 3D；2D 结果由
   明确的更新动作生成。
3. 3D 缩放中的原子、普通键和氢键仍同步缩放；连续触控板事件不会为每个 trace
   分别启动完整重绘。
4. 选区高亮只携带实际选中的原子周期实例，不再为所有未选原子维护零尺寸高亮。
5. “主体强调”保存少量主体索引和背景强度，运行时不为每个背景原子生成一条状态记录。
6. 大体系侧栏不创建包含全部原子的超长多选组件。
7. SVG、PNG、PDF 和工作状态快照仍使用完整数据；任何交互期简化都不得进入最终导出。
8. 不新增运行时依赖，不修改用户原始构型，不自动降采样，不静默关闭普通键或氢键。

## 2. 已验证瓶颈

2026-08-25 在当前开发机上使用内存生成的三层 slab 与双层水体系测得：

| 源原子数 | 成键/PBC 上下文 | 3D 构建与 JSON | 2D 与预览 PNG | 后端总计 |
| ---: | ---: | ---: | ---: | ---: |
| 594 | 0.16 s | 0.99 s | 4.91 s | 约 6.1 s |
| 2376 | 0.65 s | 1.51 s | 21.84 s | 约 24.0 s |
| 5604 | 2.11 s | 3.27 s | 52.68 s | 约 58.1 s |

5604 个源原子按 `2 × 2 × 1` 周期显示后产生 22416 个原子实例、36184 个
普通键实例和 7568 条氢键；仅 3D 上下文、Figure 和 JSON 已耗时约 15 秒，
JSON 为 15.7 MB。

瓶颈排序：

1. `app.py` 在每次已应用状态变化后同步重建 Matplotlib 2D Figure 和 2× PNG。
2. `meia/renderer.py` 为每个原子建立独立 `Circle`，并把原子、普通键与氢键
   artist 一起排序和逐个加入 Axes。
3. Python 端每次重新解析成键、周期显示和氢键，即使变化只涉及颜色强度。
4. 前端缩放按 trace 依次调用 `Plotly.update`；原子和选择层均生成与显示实例数
   等长的数组。
5. 侧栏 `multiselect` 装入全部原子；“反选背景后调色”会把背景数量放大为状态记录数。

## 3. 方案选择

### 3.1 采用：分阶段自适应渲染

小体系保持现有自动工作流；大体系把昂贵的 2D 与导出生成移到显式操作，复用
结构拓扑，并优化前端 trace 更新。所有模式使用相同的完整结构与规则。

这是推荐方案，因为它首先移除已测得的最大阻塞项，同时不要求更换 Plotly、
Matplotlib 或 Streamlit，也不改变最终图形语义。

### 3.2 不采用：只增加“大体系模式”总开关

手动总开关实现简单，但用户必须先知道体系是否“足够大”，并容易忘记恢复图层。
本设计改用可解释的复杂度判断和显式提示，用户仍能覆盖自动建议。

### 3.3 暂不采用：整体替换 3D/2D 渲染技术栈

Three.js、VTK 或定制 Canvas/SVG 渲染器可能获得更高上限，但会扩大交互、导出、
双语和部署风险。本分支先利用现有技术栈的明确优化缝隙；只有基准仍不满足目标时，
才单独评估渲染器替换。

## 4. 复杂度模型与用户提示

新增纯 Python `DisplayComplexity`，从实际 `RenderContext` 计算：

- `source_atom_count`
- `atom_instance_count`
- `visible_bond_instance_count`
- `hydrogen_bond_instance_count`
- `estimated_2d_artist_count = atoms + 6 × visible_bonds + hydrogen_bonds`
- `manual_2d_recommended`
- `large_3d_interaction`
- `extreme_3d_interaction`

初始阈值根据现有基准确定：

- `estimated_2d_artist_count >= 5_000`：2D 改为显式更新；
- `atom_instance_count >= 5_000`：显示大体系交互提示；
- `atom_instance_count >= 20_000`：启用交互期图层简化；
- 现有 50,000 原子实例硬上限保持不变。

阈值是界面/性能策略，不改变结构、成键或导出。提示必须显示源原子数与周期展开后的
显示实例数，避免把周期副本误认为新结构原子。

## 5. 2D 预览与导出生命周期

### 5.1 小体系

复杂度低于阈值时保留现有自动 2D 预览。预览缓存键包含结构身份、已应用可视化状态
指纹和已应用 2D 相机方向。

### 5.2 大体系

大体系载入后先显示 3D，不自动阻塞生成 2D。2D 区显示：

- 当前复杂度摘要；
- “生成/更新 2D 预览”按钮；
- 最近一次预览及明确的“当前/已过期”状态；
- 过期时禁用基于旧 Figure 的导出，防止下载与当前设置不一致。

点击更新后使用完整 `RenderContext` 生成与当前设置一致的 2D 和 2× PNG。旧预览可以
继续显示用于对照，但必须紧邻“已过期”提示；提示不写入图片文件。

### 5.3 缓存边界

缓存只存当前会话的 PNG/状态指纹和按需生成的导出 bytes，不长期保留大型 Matplotlib
Figure。结构替换、工作快照替换和一键还原必须隔离或失效旧缓存。

SVG、PNG、PDF 下载只来自与当前指纹匹配的完整渲染。批处理入口保持同步完整渲染，
不使用页面预览策略。

## 6. 拓扑与样式分层

将 `resolve_render_context` 拆成两层：

1. `RenderTopology`：成键候选与可见性、周期拓扑/实例、氢键几何候选；键规则、PBC
   范围、隐藏状态或相关逐原子键例外变化时失效。
2. `RenderContext`：在拓扑上应用半径、颜色、色彩强度、相机和线宽，并实例化最终
   3D/2D 几何。

同一结构只改变颜色、背景强度、原子轮廓或导出参数时复用 `RenderTopology`。缓存键必须
显式包含所有影响拓扑的字段，不能以对象身份或不稳定 `repr` 作为科学状态键。

## 7. 主体强调与颜色强度

### 7.1 运行时紧凑表示

新增 `AtomColorStrengthProfile`：

- 一个 `default_strength`；
- 少量按源原子身份保存的 `exceptions`。

“以当前选区作为主体”保留当前小选区，主体强度为 1.0，背景使用用户设置的统一强度。
不再要求先反选几千个背景原子。后续逐原子强度操作只更新例外。

### 7.2 schema v7 边界

本优化分支暂不修改 `schema_version = 7`。导出工作状态时，紧凑运行时表示展开为现有
`color_strengths` 逐原子列表；导入后可以重新规范化为紧凑表示。因此现有 JSON 语义和
严格解析边界保持不变，但极端主体/背景快照的文件体积暂时不会缩小。

如果稳定测试后确认需要同时压缩 JSON，再单独设计 schema v8 和迁移策略，不把版本迁移
混入本性能分支。

### 7.3 视觉规则

2D 延续现有填充、轮廓、普通键和氢键随强度淡化的规则。3D 原子轮廓改用逐实例颜色：
主体保持 1 px 黑色轮廓，背景轮廓按同一绝对强度向白色混合。轮廓宽度仍为 1 px，
不会因为背景强度变化而消失或改变原子身份。

## 8. 3D 缩放与选择

### 8.1 合并 trace 更新

一次缩放帧只执行一次 Plotly 数据更新和一次布局更新。更新对象同时覆盖原子尺寸、
普通键宽、普通键描边和氢键宽，不再为每个 trace 顺序等待一次 Plotly 重绘。

触控板连续滚动采用最新帧合并，并在约 80 ms 空闲后执行最终精确同步。场景范围立即变化，
原子与键的尺寸允许最多落后一帧，但停止滚动后必须与最终缩放倍率一致。

### 8.2 稀疏选择层

选择高亮 trace 只包含当前选中源原子的可见周期实例。前端从原子 trace 的坐标、
`customdata` 和基础尺寸构建稀疏高亮；点击或框选只更新该 trace。

选择全部周期副本的现有身份规则保持不变。确认选择仍只发送源原子索引，不发送周期实例。

### 8.3 屏幕选择索引

原子屏幕投影仍是 O(N)，但投影后建立固定网格空间索引：

- 点击只搜索命中半径覆盖的网格；
- 小矩形只遍历相交网格；
- 覆盖大部分视口的框选允许退化为 O(N)。

### 8.4 交互期图层简化

只有显示实例数达到 20,000 时，在主动旋转/缩放期间临时隐藏普通键描边和氢键；
彩色普通键与原子继续显示。停止交互约 120 ms 后恢复完整图层。该状态不写入 JSON、
不改变图层开关，也不影响截图和导出。

## 9. 大体系侧栏选择

原子数低于 1,000 时保留现有完整可搜索多选。达到 1,000 时：

- 不向 Streamlit 发送全部原子选项；
- 保留 3D 点击/框选、序号范围、按元素、反选和清空；
- 增加最多 200 项的分页原子窗口；
- 分页窗口提供明确的“添加到选区/从选区移除”，不会覆盖其他页的选择；
- 始终显示当前选区数量，并提供前若干原子摘要。

分页和序号输入都使用一基序号；内部与 3D 事件继续使用零基索引。

## 10. 2D 渲染器后续优化边界

本分支先通过按需生成和缓存移除实时阻塞。批量 Matplotlib collection 优化只有同时满足
以下条件才进入最终实现：

1. 与当前逐 artist 渲染的像素差异在受控参考图上通过；
2. 原子/键深度遮挡规则不变化；
3. SVG 每根键六对象编组、原子 GID 和元数据保持；
4. PNG、PDF、透明背景和空原子层测试保持通过。

如果 collection 无法保持 SVG 可编辑性，则只允许用于明确标注的页面草稿预览；最终 2D
和所有导出继续使用完整 renderer。不得把草稿预览描述为最终结果。

## 11. 测试与基准

### 11.1 自动测试

- 复杂度阈值与周期实例计数；
- 大体系不自动调用 2D renderer，小体系保持自动预览；
- 缓存指纹、失效和过期导出保护；
- topology cache 对颜色变化复用、对键/PBC 变化失效；
- 紧凑强度 profile、v7 展开/导入往返和主体强调；
- 3D 逐实例轮廓颜色；
- 单次 Plotly 批量更新、最终空闲同步、稀疏选择 trace；
- 分页选择的添加/移除语义；
- 中英文词典键一致；
- 现有 2D/SVG/工作快照契约回归。

### 11.2 基准脚本

新增可重复的 `scripts/benchmark_large_system.py`，生成固定 seed 的 slab + 水体系，报告：

- 源原子数、周期实例数、普通键/氢键数；
- topology、3D Figure、JSON、2D 和预览 PNG 时间；
- 3D JSON 大小和峰值内存；
- 自动/手动 2D 策略判定。

常规测试只验证行为，不使用脆弱的绝对秒数断言。上线候选比较相同机器、相同依赖、相同
结构的前后基准，并使用全新 Streamlit 进程进行真实浏览器验证。

## 12. 实施阶段与合并边界

1. 复杂度模型、2D 按需生成与缓存。
2. 紧凑色彩强度与主体强调。
3. 3D 批量更新、稀疏选择和大实例交互期简化。
4. 大体系侧栏分页选择与双语提示。
5. 拓扑缓存、基准脚本和真实性能复核。
6. 仅在视觉等价证据充分时尝试2D批量 artist 优化。

每一阶段采用测试先行，并形成独立提交。分支在项目所有者完成真实大体系测试前不合并
`main`；不强制推送，不改写公开历史。稳定测试后再决定是否创建 PR、是否更新版本以及
是否把本设计的长期部分并入 `docs/SPEC.md`。

## 13. 已知风险

- Plotly 5.24.1 的多 trace 更新必须用真实浏览器验证，单元测试不足以证明 WebGL 性能。
- 3D 逐点轮廓色会增加 payload；需要以背景辨识度收益与 JSON 增量共同评估。
- v7 展开式快照保留兼容性，但主体/背景极端场景的 JSON 文件仍可能较大。
- Matplotlib collection 可能破坏精确 z-order 或 SVG 分组，因此属于受视觉证据约束的阶段。
- `npm ci` 当前报告一个上游 high severity 漏洞；本任务不运行 `npm audit fix --force`，
  依赖升级应独立审查锁文件、前端构建和离线组件加载。
